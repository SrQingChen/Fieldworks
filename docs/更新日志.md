### [回归修复] 管道/机器 blockstate 被旧生成器覆盖（2026-10-12 晚，用户反馈后修复）

- **现象**：V0.2.0 首包中管道回到"静态管道"（六向连接失效）、机器失去 active 激活态变体。
- **根因**：T1 修配方时全量重跑了 v1 旧生成器 `gen_data.py`——其 `SIMPLE_BLOCKS` 循环把 gas/fluid 管道当简单方块写**单变体 blockstate**（覆盖 v2 multipart）、`MACHINE_BLOCKS` 循环写 **facing-only 4 变体**（覆盖 v2 facing×active 8 变体）。服务器冒烟不烘焙模型故零报错误导。
- **修复**：①`gen_data.py` 归属修订——管道（gas/fluid）移出 SIMPLE_BLOCKS、机器 blockstate 写入删除（模型仍归它）、交叉模型循环仅留 vent_pipe；②重跑 `gen_assets_v2.pipe_models()+build_active()` 恢复 multipart/8 变体，随后重跑 `gen_pipes_v3.py` 恢复 v3 管道贴图（pipe_models 会重写平涂贴图）；③`qa_assets.py` 新增**回归哨兵**：管道必须 multipart、27 台机器必须 8 变体，再被覆盖即审计 FAIL。
- **验证**：gen_data 复跑后 multipart（13 段）与 8 变体幸存（事故复现测试通过）；jar 内抽查确认 multipart/8 变体/v3 青色贴图齐备；qa_assets ✓。

**用户实测反馈六类缺陷 → 六项修复（根因全部反编译/源码比对确认）：**

### [R1/T1] 机器 UI 文字严重错位（修复）
- **根因**：26.1.2 原版 `AbstractContainerScreen.extractContents` 调用 `extractLabels` 前已把 pose 平移到 (leftPos, topPos)；`MachineScreen.extractLabels` 又手动加了一次 → 标题/背包标签双倍偏移（偏移量=窗口屏幕位置，随窗口尺寸乱跑）。
- **修复**：`extractLabels` 改用相对坐标（与原版默认实现同语义）。`extractBackground`（未平移）绝对坐标不变。

### [R2/T2] 配方族体系重构（对标 AE2 AERecipeTypes）（修复）
- **根因**：全部机器配方共用单一 `fieldworks:machine` 类型（AE2 实为每配方族一个 RecipeType）。
- **重构**：新增 `MachineRecipeFamily`（18 族：电解族=电解器Ⅰ/Ⅱ/Ⅲ+等离子矩阵共 4 机一族，其余 17 台工艺机各自成族）；`FWRecipes` 每族注册 RecipeType+Serializer（serializer 复用同一基础 MapCodec，经 `forFamily` xmap 把族引用烙进配方实例）；`MachineBlockEntity.findRecipe` 按 机器→族→byType 精确查询；`gen_data.py` MR() 按机器推导族 type 重生成 158 条（86 条机器配方 × 18 族 + 72 合成）。
- **本地化**：18 个族标题键 `jei.fieldworks.<族>.title` + JEI tooltip 键（能耗/时长/适用机器/流体出入）全部入 gen_lang.py 底表双语生成——此前这些键根本不存在（JEI 标题显示原始键名即用户所见"本地化信息错误"）。

### [R3/T3] JEI 类目全面重做（对标 AE2 InscriberRecipeCategory）（修复）
- **根因**：旧单类目 `setRecipe` 槽位坐标与 `draw()` 手绘槽框系统性错位 1px 且行列混排；所有机器共用一个 146×64 通用类目。
- **重做**：每族一个类目（`RecipeType.createFromVanilla`，AE2 同款）；槽位一律 `setStandardSlotBackground()/setOutputSlotBackground()`（物品与框零错位）；布局镜像机器 GUI 模板——物品族=左能量井+横排输入+动画箭头(AE2 createAnimatedDrawable)+右列输出，流体族=左入计量槽+BI 双向箭头+右对齐出计量槽列(≤3)+底部物品行+能量图标（图集新增 JEI_BG_TALL 146×88，空闲区(356,64)）；流体用 `setFluidRenderer(16×58)+addIngredients(NeoForgeTypes.FLUID_STACK)`（TransformCategory 范式，mB 量入 tooltip）；催化剂=族机器→族类目；GUI 排除区保留。
- **新 QA**：`qa_jei_layout.py` 模拟 86 条配方在两类布局中的槽/部件矩形，断言零重叠零越界（首跑抓到 2 处真实冲突——流体入槽×能量图标、混排配方输出槽×计量槽，已调整 BI 箭头/输出行/图标坐标后全过）。

### [R4/T5] 教程书多方块投影"反相移动"（根治，Patchouli 库缺陷绕行）
- **根因确认**：Patchouli 26.1-94 `MultiblockVisualizationHandler.renderMultiblock` 把 `RenderLevelStageEvent.getModelViewMatrix()`（=纯相机旋转阵）手动 mulPose 进 pose，而 26.1 渲染管线 `core/block.vsh` 已 `ProjMat * ModelViewMat` 再乘一次 → 相机旋转被应用两次（视角转 θ 幽灵转 2θ，移动方向镜像）。对照原版活塞移动方块（BlockFeatureRenderer：pose 仅相机相对平移）与 NeoForge 官方 `SubmitCustomGeometryEvent`（直接给"用于几何提交的 pose"）双重证实——**库自身缺陷，数据包侧无法规避**。
- **自研替换**：`FWMultiblockGhost`（客户端处理器）——渲染走 `SubmitCustomGeometryEvent`（相机相对 pose，零双重旋转），方块幽灵复用 Patchouli 公开 `GhostBlockGeometry`（translucentMovingBlock）；**锚定/旋转语义与 `GiantControllerEntity.checkStructure` 完全一致**（锚点=控制核心落位、同一 4 向旋转变换——所见即所校验）；交互：书页眼睛按钮开关→右键方块锚定(按玩家朝向取初始旋向)→Shift+右键旋转→超 64 格自动收起；锚定/旋转反馈缺失统计。
- **书页接管**：自定义页类型 `fieldworks:multiblock`（继承官方 PageMultiblock 仅覆写 `handleButtonVisualize`；书内 3D 预览 PiP 沿用父类——该路径无缺陷），经 `ClientBookRegistry.pageTypes`（公开可扩展映射）注册，未装 Patchouli 自动跳过；`gen_giants_v3.py` 片段改 emit 新类型+`multiblock_variant` 字段，`qa_book.py` 认新类型并校验 variant；书内操作说明同步更新（gen_book.py）。

### [R5/T4] 机器 GUI 功能件本地化补全（修复）
- **根因**：代码引用的 40+ 键（IO 浮窗标题/提示/6 面/4 模式、3 页签、投影 8 消息、能量/储罐 tooltip、蓝图 6 变体名+tooltip+用法、Jade 2 键、book_given）从未写进 gen_lang.py 底表——lang 重生成后缺失，界面上直接显示原始键名。
- **修复**：全部补入 gen_lang.py 双语底表（zh/en 各 435 键），重跑顺序 gen_lang → gen_book（book 键读改写合并必须后跑）。

### [R6/T6] 管道物品栏贴图（修复）
- **根因**：`models/item/gas_pipe.json` parent 指向 v1 遗留 `block/gas_pipe.json`（8³ 大方块+平涂贴图），与世界 v3 multipart（6×6 中心+细臂）完全脱节。
- **修复**：`gen_assets_v2.pipe_models()` 新增 `block/{fam}_item.json` 直段组合模型（中心 6×6+南北两臂=世界直管真实形态）+物品模型+26.1 物品定义三处统一指向；删除 v1 遗留模型；`qa_assets.py` 哨兵（管道物品模型必须 parent `_item` 型号且遗留模型不得存在）。

### [回归根治] gen_assets_v2 归属修订（261012 事故的根治）
- **事故复现**：本轮 pipe_models 后全量重跑 gen_assets_v2，其 `__main__` 仍执行 v2 遗留段落 `build_atlas/build_recipes/build_structures`——旧深色图集、旧配方(fieldworks:machine)、v2 巨物结构(无 controller)瞬间覆盖 v3 产物（与 261012 管道/机器 blockstate 事故同根源，上次只修了归属没修 main）。
- **根治**：`__main__` 缩减为仅 `build_active/pipe_models/build_projection_assets`（图集→gen_atlas_v3、配方→gen_data、巨物结构→gen_giants_v3）；按正确顺序全量重生成恢复。
- **同类修复**：`build_projection_assets` 的空 faces 元素（26.1.2 非法——261012 热修只改了 JSON 没改生成器，本次复跑再次写坏）改为空 elements 表，`qa_assets.py` 加哨兵。
